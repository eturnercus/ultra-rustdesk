# StealthDesk — форк RustDesk с транспортом, устойчивым к блокировкам

Исходники RustDesk: `upstream/` (коммит 55786aa, 2026-11-03), лицензия AGPL-3.0.

## Что выяснилось при изучении кода

1. **Все соединения проходят через `hbb_common::Stream`** (`libs/hbb_common/src/stream.rs`):
   enum с вариантами `Tcp`, `WebSocket`, `WebRTC`. Это главная точка встраивания:
   новые транспорты добавляются как новые варианты, и остальной код (видео, ввод, файлы)
   не меняется.
2. **Прямое подключение по IP уже есть** (`src/rendezvous_mediator.rs`, `direct_server`,
   порт 21118), но:
   - **оно не зашифровано end-to-end.** Сервер вызывает `create_tcp_connection(..., secure=false)`,
     клиент показывает «Insecure Connection» (`confirm_insecure_connection` в `src/client.rs`).
     Ключи в RustDesk подтверждаются подписью ID-сервера. Без сервера проверять нечем,
     и сессия идёт **открытым текстом**;
   - голый TCP на фиксированном порту с узнаваемым протоколом легко определяется DPI.
3. **Обмен ключами** (`Client::secure_connection`): NaCl box + secretbox, личность пира
   подписывает сервер. Для режима без серверов нужна своя схема доверия.

## Архитектура транспорта

```
 Видео / ввод / файлы (код RustDesk без изменений)
                │
        hbb_common::Stream  ← новые варианты
                │
   ┌────────────┴─────────────┐
   │  Внутренний слой: E2E    │  Noise XX (X25519 + ChaCha20-Poly1305),
   │  + закреплённые ключи    │  ключ пира проверяется по отпечатку
   └────────────┬─────────────┘
                │
   ┌────────────┴─────────────┐
   │  Внешний слой: маскировка│  уровни 1–4, автоматический выбор
   └──────────────────────────┘
```

### Уровни (пробуются параллельно, побеждает самый быстрый рабочий)

| # | Транспорт | Как выглядит для DPI | Примечание |
|---|---|---|---|
| 1 | QUIC напрямую (quinn), пробивка NAT, UPnP/IPv6 | HTTP/3 к случайному сайту | минимальная задержка, BBR |
| 2 | QUIC + обфускация (в духе Hysteria2/Salamander) | шум или HTTP/3 | если QUIC режут по сигнатуре |
| 3 | TLS 1.3 по TCP:443, Reality-подобная схема | TLS к реальному популярному сайту | при активном зондировании отвечает как этот сайт |
| 4 | WebSocket/XHTTP через CDN | обычный HTTPS к CDN | только при наличии своего VPS/домена |

Уровни 1–3 работают **напрямую между двумя устройствами**, если хотя бы у одной стороны есть
публичный IP, проброшенный порт, UPnP или IPv6. Если обе стороны за жёстким NAT (типично
для мобильного интернета), без промежуточной точки соединиться невозможно физически.
Для этого случая будет опциональный **свой** мини-сервер (не публичные серверы RustDesk):
он же даёт уровень 4.

## Безопасность

- **Шифрование E2E всегда, без исключений.** Режима «Insecure Connection» больше нет.
- **Закрепление ключей, как в SSH.** При первом подключении сверяется короткий код
  (6 цифр или эмодзи) на обоих экранах. Дальше ключ пира запоминается, и при подмене
  соединение рвётся. Альтернатива — QR-код или строка-приглашение с отпечатком ключа.
- **Пароль/одобрение доступа** остаются из RustDesk, плюс ограничение числа попыток.
- **Защита от зондирования.** Без правильного ключа сервер не отвечает протоколом
  StealthDesk: QUIC молчит, TLS-уровень проксирует запрос на настоящий сайт.
  По сканированию порта не определить, что это удалённый рабочий стол.
- **Без телеметрии и обращений к серверам RustDesk** (вырезаются адреса по умолчанию,
  проверка обновлений).
- Внешний слой маскировки — это **не** защита данных, данные защищает внутренний E2E-слой.
  Даже если маскировку раскроют, содержимое останется недоступным.

Остаточные риски: открытый наружу порт — это поверхность атаки (смягчается тем, что без
ключа сервер молчит). Безопасность зависит от того, что вы один раз правильно сверили код.

## Задержка

- QUIC без head-of-line blocking, BBR, `TCP_NODELAY` для TCP-уровней.
- Аппаратное кодирование и адаптивный битрейт RustDesk сохраняются.
- Ввод мыши и клавиатуры — отдельный приоритетный поток (QUIC stream), чтобы видео его не задерживало.
- Ожидаемо: в локальной сети меньше 10 мс сети, через интернет примерно ping + 10–30 мс.

## Этапы

0. Тулчейн и сборка «чистого» RustDesk под Windows (проверка, что всё собирается).
1. Внутренний E2E-слой с закреплением ключей + прямое подключение по IP. Уже это закрывает
   дыру с открытым текстом.
2. Уровень 1 (QUIC) и автоматический выбор транспорта.
3. Уровень 3 (TLS:443, защита от зондирования), затем уровень 2.
4. Сборка под Linux.
5. Сборка под Android (Flutter + Rust через NDK).
6. Опционально: свой мини-сервер для NAT-to-NAT и уровень 4.

## Открытые вопросы

- Уровень 3: свой Reality-подобный протокол на Rust (rustls) или встроить sing-box (Go)
  как библиотеку. Своё — проще собирать и меньше размер. sing-box — проверен в бою.
- Стоит ли вообще оставлять совместимость с обычным RustDesk (вероятно, нет: проще и безопаснее).
